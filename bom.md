## 18b. Current Coefficient-Flash Decision (Supersedes Item 18a MPN)

The selected carrier part is **Macronix `MX66UM2G45GXRI00`** (no `-T` suffix),
four devices, one shared bus and four existing chip-selects. The interface in
this revision is **x1 SPI**, not x4 QSPI; use 4-byte Fast Read `0x0C` with eight
dummy clocks at a 100 MHz carrier SCK target. The device also supports x8 OPI,
which is not used by this design. The selected part is linked at
[DigiKey](https://www.digikey.com/en/products/detail/macronix/MX66UM2G45GXRI00/18109953).
SIO0/SIO1 map to MOSI/MISO; SIO2/SIO3 remain static high in x1 mode;
SIO4-SIO7, DQS and ECS# are no-connect. VCC/VCCQ share V18, GND/VSSQ share
GND, RESET# is strapped high, and the schematic includes separate 100-nF
decouplers for VCC and VCCQ per device. The 100-MHz target still requires
post-route MISO timing sign-off.

The 1-Gb alternate is `MX66UM1G45GXDI00`. Its 24-ball map and 6 x 8 mm,
5 x 5 / 1.0 mm land pattern match the 2-Gb part; no PCB pin or CS changes are
needed. Build that population with `CFLASH_DEVICE_ADDR_BITS=27` instead of 28
(for the current Vivado scripts, set that environment variable) and limit the
coefficient image accordingly. With 64-KiB-sector-aligned,
11,862,016-byte records that do not cross chip boundaries, four 2-Gb devices
hold up to 88 full-size records (22/device); four 1-Gb devices hold 44 (11/device).
The 2-Gb population is the default and supports the planned 64-record library.
This per-device limit supersedes item 18a's aggregate-only 90-record estimate;
the controller does not split a single read across chip-select boundaries.
The prior Micron MPN and its footprint/pin map are superseded.

### Round 30 ratified design: RTZ coding + SN74LVC1G74 per cell

Architecture: **one FPGA data pin per cell (128 total, LVCMOS18)** carrying
the **RTZ-encoded** pattern (selected cell → 6-of-8 mclk cycles high per
cell period; unselected → low); **octal 1.8→3.3 V translators at the SoM
connectors (FPGA side of the board, SN74AXC8T245-class, 8/channel — RULED
2026-10-09, replaces the 128 per-cell AXC1T45)** feed the **SN74LVC1G74** D
inputs over 3.3 V runs into the cell array; the **128 FPGA → translator 1.8 V
lines are length-matched** (user ruling); the FF —
clocked from the LMK1C1108 tree at mclk — retimes the pulse and its true
Q/Q̅ outputs drive the DMMT5551 steering pair (§2) through the rs/rp
network. Translator/data-path timing errors are retimed away by the FF;
only the FF's own edges reach the cell.

Why RTZ (Round 30, 4-leg verification, `progress.md`): every selected cell
emits an *identical, self-contained* charge pulse per sample, so
(a) rise-vs-fall duty asymmetry — the defect that killed every NRZ CMOS
candidate at 1.1–1.4e-2/ns — becomes a pure **gain** error (−2.43 % at the
worst measured dtrf, k-variation ≤ 3.3e-4, sim-verified); (b) per-cell
static spreads (duty, Q/Q̅ trace skew) become DEM-shaped mismatch;
(c) pulse position is charge-invariant → clock skew is benign. Costs:
−2.5 dB amplitude (75 % duty) and real width-jitter sensitivity (needs
tree broadband floor ≤ 150 fs — actual 50–80 fs ✓; per-FF additive jitter
≤ 1 ps — bench-verify).

Why single-FF packages (MANDATORY): under RTZ all selected cells switch
simultaneously; on a shared die the SSN edge pushout (β·switching-count,
rise-vs-fall coefficients differ) makes pulse WIDTH depend on packmate
activity → code² distortion at 75–100 dB class for a quad (even Δβ =
0.05 ps/cell → 104.7 dB, `rtz_noise.py`). One FF per package reduces SSN
to a per-cell static effect (DEM-shaped). Each FF package gets local rail
isolation (R/ferrite + C, values at open item #11) so board-rail droop
stays width-symmetric.

Derived layout tolerances (Round 30): Q/Q̅ intra-pair trace mismatch
≤ ~700 ps ≈ 12 cm; clock-tree skew ≤ ±5 ns ≈ ±80 cm; data traces
untimed (retimed away). Only the analog cell matching constraints (§2)
remain sub-ns/precision class.

**LOCKED layout rule (2026-10-09, user: "beat the 5 ns by a country mile; equalise
SSN timing") — the Round-30 tolerances above are the *functional* limits, NOT the
layout targets.** Data path, FPGA pin → translator → FF, length-matched on both
segments: **FPGA pin → AXC8T245 input (1.8 V, 128 lines): ±2.5 mm (≈ ±16 ps),
within each octal group and across all 16 groups**; **AXC8T245 output → LVC1G74 D
(3.3 V, 128 lines): ±5 mm (≈ ±33 ps)**; Q/Q̅ intra-pair ±1 mm. Rationale: the
trace is then 20× below the FPGA pin-to-pin Tco spread (~300 ps) and the
translator channel skew (~300–500 ps), so all 128 D edges — and the translators'
SSN event — land at one repeatable point in every cell's setup window, far from
the sampling edge. SSN equalisation: 8 lines per octal, 8 octals per channel,
identical decoupling per octal, channels mirrored; translator B-sides on their
own ferrite/C island of `V33FF`, separate from the FF islands. **Clock tree
matching RE-INSTATED (user, 2026-10-09): XO → root LMK1C1108 → leaf LMK1C1108 →
FF CLK, all 128 end-to-end paths matched to ±5 mm (≈ ±33 ps), both channels
included; the two root legs and the 16 leaf feeds matched to ±2.5 mm.** The
Round-30 "length matching retired" note is reversed: static per-cell clock skew
interacts with sort-shaper DEM (cell assignment changes every sample), so it is
removed rather than tolerated; the remaining leaf-to-leaf skew is then the
LMK1C1108 part-to-part figure (280 ps max) alone.

### Round 29 EP52 design (SUPERSEDED by Round 30 ratification; kept for record)

Architecture (Rounds 27–29): **one FPGA data pin per cell (128 total,
LVCMOS18)**; reclock FF is a **differential LVPECL D-FF** whose true/complement
outputs drive the BJT steering pair (§2) through a resistive level-shift
network. Rationale (Round 28 sims): the cell needs Q/Q̅ skew ≤ ~0.4 ns with
matched complementary edge shapes to hold |asym| ≤ 1e-3; ECLinPS-EP guarantees
≤ 30 ps skew and inherently matched differential edges (→ asym ~1e-4, back at
the verified 151.7 dB glitch budget). No CMOS translator is needed: the FPGA’s
1.8 V output is resistively shifted into the FF’s differential D input against
an external threshold reference (see finding below).

> **VERIFIED FINDING (Round 30): the MC100EP52 has NO V_BB output pin.**
> SOIC-8 pinout is CLK/CLK̅, D/D̅, Q/Q̅, VCC, VEE only (the IBB row in the
> maximum-ratings table is EP-family boilerplate).
>
> **THRESHOLD-RAIL DESIGN (Round 30, closes open item #8).** Three buffered
> rails per channel replace the assumed on-chip V_BB (all derive from the
> clean FF 3.3 V LDO rail — partial ratiometric tracking):
>
> - **Offset rail 2.49 V** (revised from 2.31 V): feeds all 128 × 1 kΩ
>   offset legs (D and CLK networks). With the unchanged 3.6k/1k values the
>   D pin then swings 1.95–2.34 V (center ≈ 2.15 V) and the CLK pin
>   1.95–2.67 V (center ≈ 2.31 V). Load ≈ 40 mA avg per channel, partly
>   data-dependent (D legs) — buffer must source AND sink stiffly.
> - **THR_D = 2.15 V**: all 64 D̅ pins. Worst-case 64 × IIH(150 µA) =
>   9.6 mA, **data-dependent** (IIL is only 0.5 µA) — which is exactly why
>   it must NOT share a rail with the clock thresholds.
> - **THR_CLK = 2.31 V** (= CLK mid-swing): all 64 CLK̅ pins. ≤ 9.6 mA,
>   periodic (benign). Kept at mid-swing for symmetric noise margin; the
>   larger clock swing keeps pin slew ≈ 0.6–1.4 V/ns (LMK 20–80% edge
>   0.3–0.7 ns × network attenuation 0.217).
>
> Margins (verified limits): VIHCMR 2.0–3.3 V — low-state more-positive
> input = 2.15 V (D) / 2.31 V (CLK), ≥ 150/310 mV above the 2.0 V floor
> (old design sat exactly AT it); VPP(min) 150 mV vs 390 mV (D) / 720 mV
> (CLK) differential swing ✓. Accuracy: 1% divider + LDO ≈ ±35 mV — inside
> the ±150 mV window ✓.
>
> Jitter budget: CLK̅ threshold noise converts at σt = σv / slew (worst
> 0.6 V/ns) — buffered divider + per-pin RC keeps σv < 10 µV → < 17 fs,
> negligible vs the 0.2–1 ps FF jitter. Slow drift is common to all FFs in
> a group = static skew, DEM/inter-bank benign (Round 23 ruling).
>
> Realization per rail: E96 divider from FF 3.3 V rail → RC (1 µF, fc
> ≈44 Hz) → op-amp buffer (dual handles THR_D+THR_CLK; OPA1678-class, MPN
> final at §9) → 2.2 Ω into 10 µF bulk (cap-load isolation, DC feedback
> after the resistor) → star distribution → **10 Ω + 100 nF at every FF
> pin** (kickback isolation; 150 µA × 10 Ω = 1.5 mV static, negligible).

# 21. AP ↔ FPGA control SPI isolation (NEW 2026-10-05, user)

**CLOCK/RATE OWNERSHIP — REAFFIRMED AND LOCKED 2026-10-16 (user).**
AP reports the PCM stream rate/format; FPGA validates it and selects the
appropriate carrier MCLK, total interpolation and I2S BCLK/LRCLK as one coherent
configuration. FPGA remains I2S master; AP is slave transmitter. The carrier
oscillators supply the low-jitter converter/reclock MCLK; the FPGA does not
replace that analog clock source, and no separate MCLK is exported to the AP.
Maximum native input is **384 kHz**: 44.1/48, 88.2/96, 176.4/192 and 352.8/384 kHz
use x128/x64/x32/x16 total interpolation into fixed 5.6448/6.144 MHz conversion.
Two 32-bit I2S slots require BCLK=64*Fs (maximum 24.576 MHz). AP filter choice
remains policy; FPGA must validate filter/rate compatibility, reject unsupported
requests and report the applied configuration/readiness after a muted transition.
This supersedes higher native-input-rate claims; it is a design ruling, not
completed RTL or isolation-timing sign-off. See
[system specification Section 4.2](docs/SYSTEM_ARCHITECTURE.md#42-rates-and-capacity)
and [implementation findings R01–R04](docs/IMPLEMENTATION_REVIEW.md#12-open-findings-and-review-actions).

The coefficient QSPI (item 18) is FPGA-only — no isolator. The **AP → FPGA
register SPI** (SCLK, MOSI, CS → FPGA; MISO ← FPGA; optional IRQ ← FPGA)
crosses the AP/digital-board boundary and **must be isolated**. Target **50 MHz
SCLK** (user).

**Timing — why 50 MHz is not "just pick a fast isolator":** standard SPI
samples MISO on the edge opposite the one that launched it, so the loop
SCLK→isolator→FPGA(t_CO)→isolator→AP(t_SU) must fit in **half a period = 10 ns**.
Best-in-class 150 Mbps isolators have t_PD ≈ 8–13 ns *each way*; two crossings
plus FPGA t_CO (≈ 4–6 ns from an IOB register) is **≈ 22–32 ns** — three times the
budget. Standard-timed SPI through any isolator tops out around **15–20 MHz**.
The forward path (SCLK/MOSI/CS) is not the problem: same package, channel skew
≤ 2 ns, fine at 50 MHz.

**RULED 2026-10-05 (user): single SPI at a realistic frequency.** QSPI
rejected (bidirectional lanes need 11 isolator channels + direction control;
throughput only matters for coefficient provisioning). **Isolator: TI ISO7741
(RULED 2026-10-05, user: TI)** — 3 forward / 1 reverse, 100 Mbps, t_PD ≈ 10.7 ns
typ / 16 ns max, PWD ≤ 4 ns, 1.71–5.5 V level-translating sides, SOIC-16 (DW)
or QSOP-16 (DBQ); 5 kV basic. ISO7841 (8 kV reinforced, wide body) only if
safety isolation is ever required — same pinout class. Figures VERIFY against
SLLSEQ0/SLLSEW6 at the AP section. Hardware identical for both speed modes:

- **Guaranteed mode: 10 MHz, standard SPI timing** — works with any AP SPI
  master; designed to datasheet-max delays (2 × 16 + 5 + 3 = 40 ns = half-period
  at 12.5 MHz with zero margin → **10 MHz** guaranteed; 12.5 MHz will work on
  typical parts). One 10M-tap filter ≈ 9.4 s, full 64-filter set ≈ 10 min.
- **Fast mode: 50 MHz, if the chosen AP's SPI master has a programmable RX
  sample delay ≥ 2 cycles** (Rockchip SPI, AMD PS QSPI loopback, NXP FlexSPI,
  Allwinner — VERIFY; not Raspberry Pi / STM32 / i.MX ECSPI / TI McSPI) with
  **boot-time MISO training** (FPGA returns a known pattern, AP scans its
  sample-delay setting, picks the centre of the passing range — required because
  the 26–37 ns round trip straddles 1.5 cycles over PVT). Filter ≈ 1.9 s, set
  ≈ 2 min. Valid window at 50 MHz ≈ 12 ns after PWD (4) / skew (2) / t_CO (2)
  erosion. SCLK at 50 MHz is a 100 Mbps toggle = exactly the ISO7741 rating;
  fine, but no headroom above 50 MHz.
- **AP selection criterion added:** SPI master with programmable RX sample delay.
- FPGA side: IOB-registered MISO (fixed t_CO), optional ODELAY for fine
  alignment; training pattern register in the SPI register map.

**REVISED 2026-10-09 (MAX22445 selected); RE-RATED 2026-10-30 (datasheet re-read + user: run the bus as fast as it can for FPGA updates):**
the old "50 Mbps at 1.8 V" figure was wrong — DRMAX at 1.71–2.25 V is **150 Mbps**, so isolator bandwidth is NOT the gate (a 50 MHz clock = 100 Mbps passes, and the 1.8 V PWD is ≤ 2 ns, not 6.6). The real ceilings: **(a) FPGA-side oversampling** — `spi_slave` samples SCLK/CS/MOSI into clk_200m through 2–3-FF synchronizers and edge-detects: a reliable edge needs ~3×5 ns = 15 ns per half-period → SCLK ≤ ~33 MHz absolute, and MOSI is sampled ~10–15 ns after the real edge so the half-period must exceed that → **spec'd fast mode = 25 MHz SCLK** (20 ns half-period = 4 samples; comfortable margin); **(b) MISO round trip** — 2× tPD ≈ 44 ns worst at 1.8 V + FPGA sync/shift ≈ 60 ns = ~1.5 SCLK periods at 25 MHz → **the AP must sample MISO 1–2 cycles late** (XMOS does this trivially in port timing; it was already a selection criterion). Guaranteed mode 10 MHz (no AP smarts) stands; 50 MHz is out — not the isolator, the slave's oversampling; going faster needs an SCLK-clocked slave domain, not justified for a register bus. Throughput at 25 MHz ≈ 1.6 µs/frame ≈ 15 Mbps payload — coefficient-set upload lands in ms, flash writes are bounded by the flash itself. Fallback if more is ever needed: FPGA side on V33D + AXC translator block → 3.3 V timing (200 Mbps grade), same footprint.
